## 1. 発表前にやること（順番どおりに）

### 1-1. デモ用データを作り直す

```bash
node scripts/seed-demo.mjs
```

セキュリティルールを適用済みでエラーになる場合は、アプリに登録済みのアカウントでログインして実行する。

```bash
SEED_EMAIL=あなたのメール SEED_PASSWORD=パスワード node scripts/seed-demo.mjs
```

実行後、リールの表示順は次のようになる。

| 順 | 曲 | 価格 | 値動き |
|---|---|---|---|
| 1 | Night Drive | 124pt | 右肩上がり ← **デモの主役** |
| 2 | Starlight | 187pt | 終盤で急騰（新星） |
| 3 | Sunset Walk | 141pt | じわ上げ |
| 4 | Ocean Eyes | 112pt | 下げてから回復 |
| 5 | Fading Echo | 103pt | 横ばい |
| 6 | New Dawn | 96pt | 下げてから反発 |
| 7 | Color Loop | 78pt | 下落 |
| 8 | Midnight City | 62pt | 大きく下落 |

全部を上げていないのは、**負けている曲があるほうが市場として本物に見える**ため。
実データの「団子」「ピエロ」は変更していない。

### 1-2. セキュリティルールを反映する（株主投票を追加したため必須）

株主投票は `songs/{songId}/polls` サブコレクションに保存する。
Firestore はサブコレクションに親のルールが継承されないため、**ルールを反映しないと投票が動かない**。

```bash
firebase deploy --only firestore:rules
```

**必ず 1-1 のシード実行を先に済ませてから行うこと。**
ルールを適用すると未ログインの seed スクリプトが通らなくなる
（その場合は `SEED_EMAIL` / `SEED_PASSWORD` を付けて再実行すればよい）。

### 1-3. Firestore の複合インデックスを作る（重要）

価格チャートの取得を「新しい順に60件」へ直したため、
`(songId ASC, recordedAt DESC)` の複合インデックスが必要になる。

```bash
npm install -g firebase-tools   # 未インストールなら
firebase login
firebase deploy --only firestore:indexes
```

**`--only firestore:indexes` を必ず付けること。**
`firebase deploy` だけだとセキュリティルールも一緒にデプロイされ、
未ログインの seed スクリプトが通らなくなる。

※ インデックスが無くても画面が壊れないフォールバックは入れてあるが、
全件取得になるので、作っておいたほうが速い。

### 1-4. 動作確認

```bash
npx expo start
```

- リールをスクロールして音が切り替わるか
- Night Drive で「買う」→ 価格が上がるか
- 楽曲詳細のチャートに直近の値動きが出ているか
- Night Drive の楽曲詳細に**株主投票**が出ているか。株を持っていれば投票できる
- アーティストのダッシュボード → 楽曲の「株主投票」から設問を作れるか

## 2. Web公開の手順

```bash
# 1. Webビルド（dist/ が生成される）
npx expo export -p web

# 2. デプロイ
firebase deploy --only hosting
```

公開URL: `https://tune-market.web.app`

**注意点**

- `firebase.json` `.firebaserc` は用意済み。`public` は `dist` を指している
- ルールは今回デプロイしない（`--only hosting` を付ける）
- **サンドボックス環境ではビルドが完走しなかったため、`npx expo export -p web` は必ず自分のPCで一度通しておくこと。**
  静的レンダリングはブラウザ専用APIをインポート時に触ると失敗することがある
- ビルドが通らない場合の回避策: `app.json` の `web.output` を `"static"` から `"single"` に変える（SPAとして出力される）

## 3. 当日のデモ（90秒の想定）

**触るのは1本の流れだけ。寄り道しない。**

1. リールを開く（Night Drive が先頭に出る）
2. 1〜2曲スクロールして、音が切り替わるところを見せる — **15秒**
3. Night Drive に戻って「買う」→ 50pt を選んで購入 — **20秒**
   - モーダルに `株価 124pt → 138pt（+11.1%）` と出る ← **ここが山場**
4. モーダルを閉じる。リールの価格と変化率が更新されている — **10秒**
5. 楽曲詳細を開き、チャートの右端が跳ねているのを見せる — **15秒**
6. 少しスクロールして**株主投票**を見せ、その場で1票投じる — **15秒**
   - 「株を持っている人だけが、次のジャケットを決められる」と一言添える
   - 買う前は「株を持つと投票できます」と出ているので、**買った直後だと対比が効く**
7. ポートフォリオを開き、保有と評価損益を見せる — **20秒**

### 事前準備

- ログイン済みの状態で始める（会場でログインしない）
- ポイント残高を確認しておく（50pt以上必要）
- 端末の音量、通知OFF、画面の自動ロックOFF
- 会場Wi-Fiで一度アプリを開いておく

### 保険

- **同じ流れを事前に録画しておく。** ライブが詰まったら即切り替える
- 買う金額を変えれば値動きの幅も変わる（10pt→+2.4%、50pt→+11.3%、100pt→+20%）
- 時間が押したら**株主投票を飛ばす**。ここは口頭とスライドでも伝わる

## 4. 4分の構成案

| 時間 | 内容 |
|---|---|
| 0:00-0:50 | 課題とコンセプト（無名アーティストは「聴かれない」。応援を株という形にする） |
| 0:50-2:20 | **ライブデモ** |
| 2:20-3:20 | 設計判断の話（後述） |
| 3:20-4:00 | 公開までに残っていること |

### 設計判断で話すと強いこと（実装していなくても語れる）

1. **「買っても価格が上がらない」問題に気づいた**
   当初の価格式は再生数やいいね数の統計だけで決まっていたため、1pt買っても10,000pt買っても
   価格への影響が同じだった。需給を反映する式に変えた。

2. **ポイントが無限に増える問題**
   価格が上がり続ける設計では、売買のたびにシステム全体のポイント総量が増えてインフレする。
   売買手数料という回収弁が要る。

3. **株主特典の「売ったら没収問題」**
   特典を保有中だけ有効にすると誰も売れず市場が死に、一度もらえば永久にすると
   タダ取りされる。現実の**株主優待と同じ権利確定日方式**で解いた。

4. **セキュリティを自分から開示する**
   現状ポイント残高はクライアントから改竄可能。だから学内限定公開であり、
   一般公開には Cloud Functions への移行（1〜2週間）が必須。

## 6. デザイン刷新（ライト基調）について

配色を `src/constants/colors.ts` の2系統に整理した。

| トークン群 | 使う場所 |
|---|---|
| `Colors` | アプリの大半（一覧・詳細・ポートフォリオ・ランキング・マイページ・アーティスト側・モーダル） |
| `OverlayColors` | ジャケット画像の上に重なる画面（リール・ミニプレイヤー・コメントシート） |

リールを明るくしなかったのは、**ジャケット画像を全画面に敷いて文字を重ねる構造だから**。
明るいUIにすると写真の上で文字が読めなくなる。
Spotify や Apple Music がライブラリは明るく再生画面だけ暗いのと同じ理由。

キー名は2系統で共通なので、暗いままにしたい画面は
`import { OverlayColors as Colors } from "@/constants/colors";` と読み替えるだけで切り替わる。

**コントラストは機械検査済み**（トークンの組み合わせ50組、同一スタイル内で文字色と背景色を
両方指定している12件、いずれも WCAG AA 4.5:1 以上／最低 4.54:1）。

### ライト化で見つかった「白文字が消える」系のバグ

ダークテーマ時代は `Colors.text` が白だったため、アクセント地の上に `Colors.text` を
載せる書き方が成立していた。ライトにすると `Colors.text` はほぼ黒になるので、
これらは全部読めなくなる。以下を `Colors.onAccent` に統一した。

- ランキングのタブ（週間応援・急上昇・新規）
- 楽曲一覧のジャンルタブ
- アーティスト登録・楽曲投稿・楽曲編集のジャンルチップ
- 購入モーダル・応援モーダルの金額プリセット
- アーティストダッシュボードの「進捗更新」
- タグ入力の「追加」

**`AppButton` は逆向きの問題があった。** 全バリアントで文字色を白に固定していたため、
`secondary`（明るい地）のボタンで文字が消えていた。マイページの「株価を更新する」、
楽曲詳細の「試聴」「買う」「売る」が該当。バリアントごとに文字色を分けて解決した。
