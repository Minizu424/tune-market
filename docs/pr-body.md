## 1. 売買が株価を動かす需給モデル

これまでの株価は再生数・いいね数などの統計だけで決まっていたため、次の問題がありました。

- **1pt買っても10,000pt買っても価格への影響が同じ**（`holderCount` が +1 されるだけ）
- 既存保有者の追加購入では価格が1ptも動かない
- 「買ったから上がった」という株の中核体験が存在しない

`src/lib/pricing.ts` に需給ベースの価格インパクトを追加しました。

```text
変動率 = 取引額 / (板の厚み + 取引額)      板の厚み = 400pt、1取引の上限 ±25%
```

| 購入額 | 100ptの株が | 変動率 |
|---|---|---|
| 10pt | 102pt | +2.4% |
| 50pt | 111pt | +11.1% |
| 100pt | 120pt | +20.0% |
| 200pt以上 | 125pt | +25.0%（上限） |

### 約定価格を平均にした理由

当初は「取引前の価格で約定 → そのあと価格が上がる」という実装にしていましたが、
これだと **買った直後に売るだけで確実に儲かる**（無リスクの裁定が成立する）ことに気づきました。
124ptで買って138ptで売れてしまうためです。

実際の板取引と同じく、価格を押し上げながら約定する **平均約定価格** を使うよう変更しています。

```text
平均約定価格 = (取引前価格 + 取引後価格) / 2
```

検算（124ptの株を50pt購入 → 即売却）:

| | 平均約定 | 価格 | 残高 |
|---|---|---|---|
| 買い | 130.89pt で 0.382株 | 124 → 138pt | 100 → 50pt |
| 売り | 129.97pt で 49.65pt | 138 → 122pt | 50 → 99.65pt |

往復で **-0.35pt**。裁定は成立しません。

購入・売却モーダルには `株価 124pt → 138pt（+11.3%）` を表示します。

## 2. 価格履歴のバグ修正

`getPriceHistories` が `orderBy("recordedAt", "asc") + limit(60)` になっていました。
Firestore の limit はクエリ順の先頭から取るため、これは **最古の60件** を返します。
つまり履歴が60件を超えた時点で、チャートに新しい価格が永久に出なくなっていました。

`desc + limit` に変更して取得後に反転させています。
これに伴い `(songId ASC, recordedAt DESC)` の複合インデックスが必要になるため
`firestore.indexes.json` を追加しました。インデックス未作成でも画面が壊れないよう、
全件取得してクライアント側でソートするフォールバックも入れてあります。

`PriceChart` が表示範囲（直近30件）ではなく全件の最小・最大でスケールを取っていた不整合も直しました。

## 3. 株主投票

「株を持つ意味」が値上がり益しかなかったため、保有株数に比例した票数で
制作方針に投票できる機能を追加しました。壁紙やボイスメッセージと違い、
**アーティストは設問を1つ作るだけ**で成立するのが採用理由です。

```text
songs/{songId}/polls/{pollId}                    設問と選択肢ごとの集計
songs/{songId}/polls/{pollId}/ballots/{userId}   投票用紙
```

- サブコレクションにしたのでコメントと同じく複合インデックスが不要
- **投票用紙のドキュメントIDをユーザーIDにすることで、二重投票を構造的に防止**
- 投票の変更も可能（トランザクション内で前の票を差し引いてから加算するため集計がずれない）
- 株を保有していないユーザーは投票できない（`holdings` をトランザクション内で確認）

アプリ内には「制作方針への意見表明であり、金融商品としての議決権や所有権ではない」旨を明記しています。

## 4. ライト基調へのデザイン刷新

暗い配色は「暗いこと」より **面同士の明度差が小さすぎること** が問題でした。
背景 `#061226` / カード `#111827` / 罫線 `#1F2937` では、カードが下地から浮いてきません。

トークンを2系統に分けて解決しています。

| トークン群 | 使う場所 |
|---|---|
| `Colors` | アプリの大半 |
| `OverlayColors` | ジャケット画像の上に重なる画面（リール・ミニプレイヤー・コメントシート） |

リールを明るくしないのは、ジャケットを全画面に敷いて文字を重ねる構造のため、
明るいUIだと写真の上で可読性が失われるからです。
ライブラリは明るく再生画面だけ暗い、という音楽アプリ共通の構造に合わせました。

キー名を2系統で揃えてあるので、暗いままにする画面は import を読み替えるだけで切り替わります。

### ライト化で見つかった「文字が消える」バグ

ダークテーマ時代は `Colors.text` が白だったため、アクセント地の上に `Colors.text` を
載せる書き方が成立していました。ライトにすると `Colors.text` はほぼ黒になるので全て読めなくなります。

- ランキングのタブ、楽曲一覧のジャンルタブ
- アーティスト登録・楽曲投稿・楽曲編集のジャンルチップ
- 購入・応援モーダルの金額プリセット
- ダッシュボードの「進捗更新」、タグ入力の「追加」

`AppButton` は逆向きの問題で、全バリアントの文字色を白に固定していたため
`secondary`（明るい地）のボタンで文字が消えていました。
マイページの「株価を更新する」、楽曲詳細の「試聴」「買う」「売る」が該当します。
バリアントごとに文字色を分けて解決しました。

### コントラスト検査

機械的に検査しています。

- トークンの組み合わせ 50組
- 同一スタイル内で文字色と背景色を両方指定している 12件

いずれも **WCAG AA (4.5:1) 以上／最低 4.54:1**。
検査の過程で `textFaint` と `gold` が基準を割っていたため濃度を調整しました。

## 5. レスポンシブ対応

Web を広い画面で開くと一覧の1行が画面幅いっぱいに伸びていました。
`useLayout()` で画面幅から切り替えます。

| 画面幅 | 表示 |
|---|---|
| 〜759px | 1行リスト（スマホ基準） |
| 760〜833px | 2列タイル |
| 834〜1279px | 3列タイル |
| 1280px〜 | 4列タイル（中身は最大1080pxで中央寄せ） |

一覧で最も見たい情報である価格と騰落率を強調しました。

- 価格を 14px → 20〜22px、単位 `pt` は小さくグレーに落として数字を主役に
- 騰落率を色付きのピル（▲緑 / ▼赤）に変更
- ランキングの応援pt、ポートフォリオの評価額・損益も同じ方針で拡大

ランキングはタイルにしていません。順位が縦に並んでいること自体が情報のためです。
リールも広い画面では最大440pxで中央寄せにしました。

### シードを作り直した理由

発表前に本番データを確認したところ、**シード8曲のうち7曲が初期価格100ptを割っていました**
（最安 Midnight City 39pt）。原因は `NO_ACTIVITY_DECAY = 0.99` で、
株価更新ボタンを押すたびに反応のない曲が1%ずつ下がり、複利的に減衰していたためです。

価格チャートが全曲右肩下がりになり、「応援すると価格が上がる」という主張を
データ自身が否定する状態でした。上昇・下降・横ばい・急騰が混ざる形に作り直しています。
実データの「団子」「ピエロ」は変更していません。

## 7. 明るい配色への統一

前回は「リールだけダーク」でしたが、明るい配色に統一しました。

## 9. 音源の先読み

リールは縦スクロールで次々に曲が切り替わるため、切り替えた瞬間に
ダウンロードを始めると音が出るまで待たされていました。

`useAudioPrefetch` で表示中の曲の**前後2曲**を再生せずに読み込んでおきます。

- Web … 非表示の `Audio` 要素に `preload="auto"` を指定してブラウザのキャッシュを温める
- ネイティブ … ミュートしたプレイヤーを生成（生成時点でバッファリングが始まる）

表示範囲から外れたものは解放し、画面を離れるときにまとめて破棄します。

## 10. 再設計の過程で見つけて直した不具合

### 明るい配色にしたことで文字が消えた箇所

ダークテーマ時代は `Colors.text` が白だったため、アクセント地の上に `Colors.text` を
載せる書き方が成立していました。明るくすると `Colors.text` はほぼ黒になり、全て読めなくなります。

- ランキングのタブ、楽曲一覧のジャンルタブ、各画面のジャンルチップ
- 購入・応援モーダルの金額プリセット、ダッシュボードの「進捗更新」、タグ入力の「追加」

`AppButton` は逆向きの問題で、全バリアントの文字色を白に固定していたため
`secondary`（明るい地）のボタンで文字が消えていました。
マイページの「株価を更新する」、楽曲詳細の「試聴」「買う」「売る」が該当します。

ミニプレイヤーは、ジャケット上に敷いた暗い帯の文字色が黒のままでした。

### タグの3状態の色

チップの文字色を `mode != null` で一括して白にしていたため、
**除外状態が「薄い赤地に白文字」**になっていました。3状態それぞれに文字色を割り当てています。

| 状態 | 地 | 文字 | コントラスト |
|---|---|---|---|
| 未選択 | グレー | 濃いグレー | 6.22:1 |
| 選択中 | 黒 | 白 | 18.86:1 |
| 除外 | 薄い赤 | 赤 | 4.70:1 |

### ホーム画面の要素の重なり

ヘッダー・ジャンルバー・シークバーが全て絶対配置のままで、
リールの中身と重なっていました（シークバーが「買う」ボタンに被る等）。全て通常フローに組み直しています。

さらに、タグを選ぶと絞り込みバーが3段に増えて高さが変わり、
リールが押し出されていました。**バーを常に1行の固定高**にして、
加えてジャケットが余った領域を吸収する構造（`flex: 1`）にすることで解決しています。

### リールをスクロールしても曲が切り替わらない

自動送り用のガードが解除されず残っていました。原因は3つ重なっていました。

1. `activeIndexRef` を `useEffect` で更新していたため1描画ぶん古い値が残り、
   再生側との同期処理が「自動送りが起きた」と誤判定して、
   **ユーザーのスクロールのたびにガードを張り直していた**（主原因）
2. ガードに期限がなく、一度張られるとそのインデックスに戻るまで永久に解除されない
3. Web のホイール送りがガードを解除していなかった

`activeIndexRef` を描画時に同期更新し、ガードに1.5秒の期限を設けました。

### その他

- **リールの復帰位置**: 他タブへ移動するとホーム画面はアンマウントされ、
  戻ると先頭から表示されていました。最後に見ていた曲IDをモジュール変数に逃がし、
  `initialScrollIndex` で復帰します（再生中の曲 → 最後に見ていた曲 → 先頭の順）
- **シークバー**: `pointerEvents` とパンハンドラが一時停止中しか有効でなく、
  再生中は操作できませんでした。常時操作可にし、太さだけを状態で変えています
